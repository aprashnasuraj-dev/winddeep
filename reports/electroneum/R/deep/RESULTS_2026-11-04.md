## Explicitly rejected false findings and operational caveats

- D1 first CI [41757942900](https://github.com/aprashnasuraj-dev/winddeep/actions/runs/41757942900) failed at Go source parsing due to an incorrectly constructed JSON literal in a **test fixture**. Corrected via JSON marshaling and rerun 41758093680 passed. Original failure was not a source bug.
- D4 first CI [41758390154](https://github.com/aprashnasuraj-dev/winddeep/actions/runs/41758390154) assumed 3 pending bodies, when the actual fixture had **6 bodies and 3 receipts**. The real queue behavior was correct; fixture expectation corrected and run 41758572592 passed. Original failure was not a source bug.
- Other red '.github/workflows/electroneum-reverse-independent-ci.yml' runs spawned on the isolated audit branches are unrelated to the dedicated D1-D4 workflows and are not counted as Electroneum defects, completed test work, or failures of D1-D4.
- The unknown-length HTTP oversize test verifies no valid JSON-RPC success is returned for the >5 MiB request. It does not guarantee a specific HTTP status (such as 413) for chunked transfer.
- D4's 12 race rounds with Go -race and bounded mutations support concurrency-control properties, but they do **not** simulate real network sockets, peer sessions, disk crash recovery, or full sync pipeline with hostile external peers.
- D2 limits mutated payload size and thus cannot conclude safety under arbitrary multi-megabyte input or a forged KDF parameter controlling expensive cryptography.
- D3 intentionally checks typed envelope encoding and signature replay domains. Consensus acceptance, fee policy and finality remain separate layers.

## Next unresolved high-value work

1. **Full backend live reorg:** implement in-process full BlockChain/EthAPIBackend with head transitions, measure TOCTOU window, validate whether any ordinary peer-triggered reorganization reaches the race, and assess downstream consumer behavior and confirmations.
2. **Crash/persist sync replay:** move beyond in-memory queue Close/Reset to persisted stage checkpoints and intentional interrupted writes; compare receipt/body root and canonical commitments after restart.
3. **Parser limits at realistic request sizes:** chunked HTTP streaming and nested ABI transaction/log decoding near actual endpoint limits, with hard process memory, CPU and wall-time budgets.
4. **Transaction/consensus integration:** signed priority transactions through fork transitions, reorged pool state and actual block execution (not only binary normalization).
5. **Failure triage discipline:** retain a strict positive control, named mismatch marker, minimized reproducible corpus and production-reachability assessment before promoting any new finding.
