## NEW discriminator: the production reorg removes lookup indexes and publishes removed-log events
- Immutable certified `core/blockchain.go` `reorg` (approximately lines 2050–2095) computes `types.TxDifference(deletedTxs, addedTxs)`, calls `rawdb.DeleteTxLookupEntry` for removed transactions, writes the batch, and emits `RemovedLogsEvent` for deleted logs. Thus reorg has explicit index invalidation and log-removal defenses, not only an eventual canonical-hash change.
- `core/rawdb/accessors_indexes.go:~88-116` `ReadTransaction` first resolves the lookup entry, then the current canonical hash and body, and verifies the exact transaction hash. A **fresh** post-reorg lookup cannot return an orphan absent from the replacement block, even if an old receipt remains in storage.
- `eth/api_backend.go:265-268` delegates to that canonical lookup; `:185-187` retrieves receipts by block hash. `internal/ethapi/api.go:1571-1626` performs these reads separately without an explicit final canonicality check. Retained side-chain receipts (see prior 09:57 assessment) make an in-flight read-gap **plausible**, not observed.
- Counterexample to a simplistic “reorg always creates false credit”: the RPC lookup begins after reorg and returns no orphan; a relying exchange checks canonical block hash, successful status, recipient, value, chain ID and N confirmations before credit. A transient receipt during concurrent reorg alone is insufficient to prove an externally wrong decision.

## Competing explanations and discriminating experiment
1. **R0 race exists:** a valid transaction's canonical lookup completes before reorg; a genuine chain transition occurs; the by-hash receipt survives and is returned despite the old block no longer canonical. This would establish an RPC-time inconsistency only, not necessarily financial loss.
2. **Defenses prevent the race:** actual backend synchronization, index invalidation, receipt/header lifetime or reorg sequencing prevents the response, or it returns null/error.
3. **Client defense prevents loss:** a receipt is temporarily stale, but an independently checking exchange refuses to credit, so E4 is absent.
