# Windeep platform threat model

This document tracks threats to Windeep itself. It is part of the release gate: a phase that changes an attack surface must update the relevant threat, mitigation, test, and residual-risk entry.

## Security invariants

- The HTTP service binds to IPv4 loopback only. There is no remote-listener mode.
- Scope, signed consent, crypto health, audit health, and rate governance are mandatory and fail closed before a scan and again before each tool invocation.
- Tools execute only through the catalog wrapper. Tool output and target content are untrusted data.
- Sensitive persisted material uses the encrypted store. Export surfaces receive sanitized/redacted views rather than raw encrypted evidence.
- Evidence-bearing records are never destructively rewritten by a migration.
- Model output is advisory data and never an execution authority.

## Threats

| Threat | Mitigation | Verification | Residual risk |
| --- | --- | --- | --- |
| Malicious HTML/JS/contract source contains prompt-injection instructions | Target content is treated as untrusted; Brain prompts use `PromptGuard`; P0 post-processing uses heuristic-only `LLMClient([])` and does not execute target instructions. Model-proposed execution remains scheduler/preflight gated. | `tests/test_prompt_guard.py`; P4 adversarial evidence tests; P0 scheduler preflight-spy test. | A future parser could accidentally copy attacker text into an unguarded model prompt. Any new LLM call must add a prompt-guard test. |
| Target-controlled path attempts traversal into artifact/state storage | Runtime paths are rooted by application-owned directories; target strings are data, not file paths for artifact placement. New artifact names must be content-addressed rather than target-derived. | Capture/artifact path-safety tests in P1; release forbidden-pattern audit. | Third-party tool binaries may create their own temporary files; wrappers and P1 cleanup must constrain/verify them. |
| SSRF against Windeep loopback endpoints | Scope enforcement is applied to every scheduler tool attempt; replay/capture paths must use the same guard. The dashboard itself remains loopback-only and authenticated. | `tests/test_scope_enforcer.py`, `tests/test_auth_preflight.py`, P1 replay scope tests. | An in-scope application may legitimately resolve to loopback/private addresses; resolver-state validation must remain fail closed where applicable. |
| Compromised tool binary performs argv injection | Wrapper catalog builds argv as token lists; f-string shell commands and direct subprocess use outside the wrapper layer are forbidden. P0 scheduler passes only a scope-bound target into wrappers. | `tests/test_tool_wrapper.py`; grep/release audit for direct process execution and shell construction. | A malicious binary can ignore argv semantics entirely. Binary provenance/hash capture in P1 limits repudiation but cannot make a compromised binary trustworthy. |
| Compromised tool binary leaks environment secrets | Wrappers receive a bounded runtime environment; raw environment is never persisted. P1 records only an allowlist hash. SSE finding events omit evidence/request/response fields. | v2 settings tests; P1 environment-hash and redaction tests. | A permitted tool may print a configured credential to stdout. P1 export redaction must sanitize before any outward surface. |
| Compromised tool binary spoofs stdout/stderr to look like a valid finding | Tool output is untrusted parser input; normalized findings are schema-validated by wrappers and later evidence bundles bind results to immutable raw output. No output is `eval`ed. | wrapper/parser tests; P2 provenance and artifact-range validation. | A compromised binary can emit syntactically valid false evidence. P1 binary path hash + version and P2 provenance make that detectable to a reviewer but do not prevent it. |
| Missing/failed preflight accidentally reaches a tool | `TaskScheduler` refuses to execute without a guard, authorizes the scan, reauthorizes each tool attempt, then acquires tool and host rate capacity. Guardrail denials are not retryable. | `tests/test_scheduler.py`; `tests/test_v3_p0_pipeline.py`; `tests/test_v3_p0_post_and_sse.py::test_missing_preflight_never_reaches_runner_spy`. | If a future execution path bypasses the scheduler entirely, this invariant could be lost. CI forbidden-pattern checks must cover every executable surface. |
| One failed scan branch corrupts/cancels independent evidence | P0 scheduler isolates branch failures; only dependents become blocked. Scan finishes `completed_with_errors` when independent branches succeed. Cancellation remains explicit and propagates to cancellable nodes. | P0 partial-failure and cancellation tests. | Shared third-party resources can still couple independent tasks operationally (CPU, disk, vendor throttles). P6 budgets/backpressure constrain this further. |
| SSE client misses events or receives secrets | Per-scan events are persisted with monotonic sequence numbers. Subscription registers before replay; `Last-Event-ID` replay is gap filling. Finding SSE payloads strip raw evidence/request/response/narrative proof fields, and secret-named top-level fields are masked. | P0 scan-event and SSE replay/redaction tests. | P0 redaction is deliberately conservative, not the full reproducible redaction-map system. P1 replaces this with versioned deterministic redaction rules. |
| Slow SSE client stalls a scan | Producers use bounded queues and never await clients. If a queue drops events, sequence-gap detection replays them from the encrypted event log. | P0 SSE replay test; P6 backpressure stress test. | A client that never consumes can keep its connection open until server/network timeout; it cannot block scan execution. |
| Concurrent tool rerun duplicates findings or exposes partial writes | P0 persists a tool's normalized results in one SQLite transaction and records occurrence identity by `(scan_id, tool_run_id, finding_fingerprint)`. WAL readers see committed state only. | P0 batch-upsert idempotency test; database WAL tests. | The legacy canonical finding table is globally fingerprint-deduplicated for compatibility. P1/P2 evidence records therefore carry the authoritative per-run provenance. |
| Crash between event creation and live delivery creates an SSE gap | Persistent event append occurs before live broadcast. Reconnection uses the encrypted event log as source of truth. | P0 replay tests; P6 crash/resume test. | A crash before the SQLite transaction commits means the event did not exist; stage-boundary recovery in P6 handles incomplete scans. |
| Master key is leaked | Current master-key protections remain in place. P1 introduces per-scan DEKs wrapped by the master key; scan Merkle roots provide tamper evidence and limit disclosure scope during rotation/destruction. | Existing crypto tests; P1 DEK rotation/Merkle verification tests. | A live attacker with the master key and access to all wrapped DEKs can decrypt retained scans until keys are rotated/destroyed. |
| Malicious operator redaction regex causes catastrophic backtracking | P1 redaction terms must be compiled/executed under bounded input size and a timeout-capable/bounded regex strategy; raw evidence remains encrypted and unchanged. | P1 regex-DoS fixture with an adversarial pattern and long input. | Extremely broad but computationally cheap patterns can over-redact exports; the redaction map makes this visible and reproducible. |
| Migration damages evidence | Migrations are additive/checksummed; evidence tables are not dropped or rewritten. P0 adds only `scan_events` and `tool_finding_refs`. | migration tests; release audit; review grep for DROP/rewrites of evidence tables. | SQLite/host storage corruption is outside migration logic; encrypted backup/restore and P6 recovery remain necessary. |

## P0 attack-surface delta

P0 introduces scheduler-managed concurrency, a registered Flask scan-thread handoff, encrypted replayable SSE event persistence, and deterministic post-processing. The principal new risks are race conditions, branch-failure contamination, event gaps, and accidental export of raw evidence. The mitigations above deliberately keep all tool execution behind `PreFlightGuard`, use one event loop per scan, make tool output persistence transactional, and make SSE a metadata-only evidence notification surface until the P1 redaction/custody layer is complete.
