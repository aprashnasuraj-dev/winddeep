# Windeep V6 — 10 critical release blockers

Status: **BLOCKED / DRAFT** (2026-11-03). This checklist is not a declaration of completed fixes. Do not merge the V6 PR or tag/release V6 until all ten gates are evidenced and accepted.

## Evidence baseline and scope
- User-reported Windows application: scan appears stalled, UI freezes, integrations shown unavailable.
- Supplied Windeep v4 HostGator report: 587 informational entries; 500 historical `gau` URL results, 82 `getjs` URL references, four DNS observations, one RDAP record; **zero proven vulnerabilities**. An archived HTTP 200 or URL is not a current security impact.
- Main README advertises 137 historical integrations, 109 active launch integrations, 28 catalog-only/deprecated entries. **Registered != executable != useful detector**. Host availability is environment-specific.
- Existing v5 audit (`docs/v5-engine-report-audit.md`) explicitly does not certify every backend or detector. Open PRs #27–#30 address related evidence/observation/authorization work; reconcile without blind cherry-picks.
- Never promise submission-worthy findings on arbitrary targets. Release target is defensible classification and reproducible evidence when a vulnerability actually exists, with low noise when none exists.
- All active testing requires authorized scope, consent, policy and rate limits. Test detector behavior primarily against controlled local fixtures.

## Ten critical gates (check only with linked passing artifacts)

- [ ] **V6-01 — Recover live scan state and freeze-free UI.** Trace browser main-thread stalls, SSE reconnect handling, API timeouts and event ordering. Show queued/running/completed/failed/blocked/cancelled with current tool, completed/total count, last event, elapsed time and explicit reason when blocked. Add a heartbeat and reconnect snapshot so missed SSE events cannot create permanently frozen progress. **Acceptance:** 30-minute synthetic scan with forced disconnect/reconnect and 1000+ events; UI remains interactive, progress reconciles and never reports completed before backend terminal state. Attach browser trace and test log.
- [ ] **V6-02 — Cancellation, timeout and deadlock recovery.** Audit scheduler DAG dependency failures, queue starvation, zombie subprocesses, retries, per-tool timeout, cancellation propagation and restart recovery. **Acceptance:** inject hanging command, failed prerequisite, app restart and user cancellation; bounded terminal states, subprocess cleanup and durable resumable/failed state. No infinite spinner. Attach process and scheduler traces.
- [ ] **V6-03 — Honest integration availability with actionable repair.** Check all 137 catalog entries by Windows native, WSL, Docker/Podman, managed, remote and fallback; distinguish installed/ready/unsupported/credentials-required/policy-blocked/deprecated. Never show catalog-only entries as runnable. Doctor outputs exact missing dependency, setup instruction and reason; healing requires consent. **Acceptance:** matrix from clean Windows and Linux test environments with probe, version and execution smoke per advertised ready tool; zero 'ready' tools failing with missing binary.
- [ ] **V6-04 — Backend result integrity and no false findings from fallback recon.** Preserve source, parser, stdout/stderr hash, timestamp, current-vs-archive, backend tier and HTTP verification status. Route passive `gau`, `getjs`, RDAP, DNS and wordlist outputs to asset inventory by default—not vulnerability findings. **Acceptance:** regression on the 587-entry evidence shape produces zero submission candidates, retains all recon evidence and does not artificially inflate severity/confidence.
- [ ] **V6-05 — Proof-graded detector engine.** Introduce explicit `observation -> hypothesis -> candidate -> verified -> human-approved submission` progression. Candidate requires affected endpoint, expected/observed difference, repeatable controls and authorized impact evidence. No silent promotion from tool exit code, 200 response, generic line output or AI assertion. **Acceptance:** fixtures for real and negative controls across at least five vulnerability classes, with reviewer-visible failure reasons.
- [ ] **V6-06 — Reproducible safe validation on local labs.** Prioritize authorization boundaries/IDOR, session lifecycle, sensitive information exposure, input reflection with execution-context proof, and misconfigurations with demonstrated consequences. Use non-destructive test fixtures, matched baseline/negative controls and replay isolation. **Acceptance:** controlled vulnerable+patched paired fixtures for each supported class; verified cases yield an auditable proof, patched variants yield zero confirmed findings; measure recall and false-positive rate rather than claiming coverage from tool count.
- [ ] **V6-07 — Evidence custody and scoped reporting.** Reconcile open PRs #27–#30: immutable per-tool raw artifacts, scan observation association, class-aware HTTP/browser/artifact proof, integrity closure and live authorization before exports. **Acceptance:** repeated findings across two scans remain visible in both; missing proof rejects submission; expired consent blocks ZIP and draft exports; secrets remain encrypted/redacted; positive and negative regression CI green.
- [ ] **V6-08 — Submission quality over quantity.** Add submission readiness rubric: title, affected asset, program scope, steps, expected vs observed, request/response or artifact, proof of impact, uncertainty, duplicate risk, remediation and manual approval. Keep CVSS unset without supported vector. **Acceptance:** noisy sample report exports zero ready submissions; local verified fixture exports a reviewable, redacted draft; no automatic submission and no unsupported bounty claims.
- [ ] **V6-09 — Observability and resource budgets.** Correlation IDs across scan/task/tool/UI, bounded event buffer, log redaction, per-backend latency and error metrics, memory and CPU ceilings, backpressure and rate governor visibility. **Acceptance:** load test concurrent scans and >10k mixed events, with documented P95 responsiveness, memory, CPU and no lost terminal events; explicit fail-closed scope/rate behavior.
- [ ] **V6-10 — Reproducible release qualification and rollback.** Gate installer and portable Windows builds, Linux smoke, fresh database migration, offline/no-AI mode, no-network integration behavior, 137-tool catalog contract, package hashes/SBOM and updater rollback. **Acceptance:** exact release-commit CI green, signed/hashed artifacts when applicable, clean Windows install/upgrade/uninstall verified, manual UI acceptance, documented limitations and release rollback exercised.

## Release and merge policy
1. Keep this PR **draft and unmerged** while any box is open. Do not change VERSION to 6.0 or publish binaries merely to satisfy CI.
2. Each gate requires one implementation PR or commits with: root cause, before/after test, negative control, OS/backend coverage, artifact link, and reviewer sign-off. A green build by itself is not proof of live application readiness.
3. Preserve preflight, explicit consent, rate/scope policy, encryption, redaction, evidence integrity and audit logging. Never scan a public third-party target to meet a benchmark without explicit authorization.
4. Reconcile currently open stacked PRs and establish a linear merge order before implementing overlapping runtime/evidence fixes.
5. V6 release criteria: **10/10 gates closed, no release-blocking regressions, truthful detector recall/false-positive benchmarks, and reproducible submission-ready local-lab proof**. This does *not* promise a vulnerability on every real-world site.
